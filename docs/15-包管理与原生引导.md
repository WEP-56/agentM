# 0.10.0 包管理与原生引导

日期：2026-10-09。当前为 `0.10.0-dev / versionCode 13`，已构建，并按用户随后要求覆盖安装到 `emulator-5554`、启动应用。0.9.1 的用户验收不能作为本版验收。

## 页面与原生职责

| 页面 | 当前职责 |
| --- | --- |
| 首页 | 启动/进入 Agent、Linux 终端和设备终端。缺依赖时导航至环境或对应 Agent 页签，不执行安装、卸载或停止。 |
| 配置 | Claude Code、Codex、OpenCode、Pi、DSH 五个可横向滚动的页签；未安装也有入口。安装、在线更新检查、更新、卸载、单 Agent 本地自检、Web 状态及沙箱诊断均在此页。 |
| 环境 | Ubuntu 安装/检查、Node.js/npm/Git/Python/CA 工具管理、设备信息、日志、存储统计与只读目录浏览。增加「设置向导」入口。 |
| 设置 | 保持偏好与权限管理。 |

Claude 的配置预览、冲突检查、原子写入、加密备份与提供商模板继续保留；切换 Agent 页签保留 Claude 表单草稿。其余四类 Agent 保留原生登录/配置方式，本版没有伪造四套配置表单。

`checkPackages` 已从原生允许动作中移除，改为 `checkTools` 及 `checkClaude/checkCodex/checkOpenCode/checkPi/checkDsh`。环境工具检查只运行 Node/npm/Git/Python/CA 探针。相关设备测试的动作调用同步迁移。

UI 使用原生快照中的 `busy/phase/action/operationId`。单例包管理任务与终端/Web/配置维护互斥继续生效；软件管理操作不再强制跳转环境页。

## 在线发现与更新边界

`PackageUpdates` 从固定 npm 官方源的 `/<package>/latest` 查询各 Agent；动态更新再查询 APK 指定的平台包及精确版本。请求限制 HTTPS、固定来源、响应大小与超时，不接受前端 URL、包名、脚本或依赖图。

| Agent | 可在线发现 | 可由当前 APK 安装的更新 |
| --- | --- | --- |
| Claude Code | `@anthropic-ai/claude-code` | 2.1.x 稳定补丁；固定平台包与 `package/claude` 布局 |
| Codex | `@openai/codex` | 0.161.x 稳定补丁；固定平台包与 layoutVersion 1，校验 host/rg/bwrap 等组件 |
| OpenCode | `opencode-ai` | 1.18.x 稳定补丁；固定平台包与 `package/bin/opencode` 布局 |
| Pi | `@earendil-works/pi-coding-agent` | APK 内的完整适配清单；bundle、WASM、原生组件仍固定 |
| DSH | `@deepseek-ai/dsh` | APK 内的 DSHA 依赖图与 overlays，不能直接跟随上游安装 |

这里的「可适配」表示 recipe 接受该候选，安装时仍需校验与实际运行检查；不代表该补丁已覆盖全部模型、插件、WebUI 和设备矩阵。超出系列的新版本显示为待适配。Pi/DSH 的新适配版本需先发布包含新清单的 agentM APK，之后更新受管槽位；没有远程任意 recipe 执行通道。

已安装、内置适配、上游、可适配版本分开展示，在线检查与本地自检有独立按钮。更新候选有效期 24 小时；检查失败、检查中、进程中断或过期均不能更新。离线失败保留上次成功版本和时间，但明确标为旧结果，不显示「最新」。

2026-10-09 开发机通过 Node HTTPS 实测五个查询地址均返回 HTTP 200：Claude `2.1.295`、Codex `0.162.0`、OpenCode `1.18.35`、Pi `1.1.0`、DSH `0.2.0-rc.2`。Claude 两种架构的 `2.1.295` 元数据也返回匹配包名、版本和 SHA-512。Codex `0.162.0` 超出本版接受范围，必须等待新适配。

更新沿用唯一未发布槽位：

1. 校验 npm 元数据中的 SHA-512，计算本地 SHA-256 用于槽位来源记录；固定包仍校验 APK 的 SHA-256。
2. 在新槽位解压，验证固定布局、实际版本和现有功能探针。
3. 仅在验证成功后原子发布 manifest；随后清理已确认归属的旧槽位。
4. 下载、校验、自检或发布失败时只清理未发布槽位。已安装记录、用户 home、登录、会话和工作区保持不变。旧槽位清理失败不撤销已经成功的发布。

动态补丁下载不使用 npm install/update 或包生命周期脚本，当前失败后重新下载；固定清单下载原有续传能力保留。Codex 独立沙箱检查的已有失败仍单独记录，不把可登录或版本通过解释为沙箱已修好。

## 原生引导

`NativeOnboarding`：欢迎 → 设备检查 → Ubuntu/工具准备 → 可选 Agent → 真实结果。与环境页共享 `NativeLinuxSetup/NativeTools`，与配置页共享 `NativeAgentPackage`，没有第二套安装器。

快照轮询移至 `AppRoot`，引导期间也持续读取原生任务。`agentm-native-ui-v1` 额外保存 `onboardingStep`，保留原有 `onboarded` 和偏好；既有用户不被强制重走引导。环境页的「设置向导」可手动重入，不清理任何数据。

已就绪组件直接复用；支持失败重试、返回上一步、退出重入、全部跳过、部分 Agent 失败以及稍后准备基础环境。引导完成标识仅表示用户进入工作台，环境是否可用始终由原生快照决定。通知/电池权限不强制请求，私有工作区无需共享存储权限。

## 存储浏览

`storageUsage/listStorage` 仅暴露于工作台受信任桥，Agent WebView 没有这些接口。

- 固定分类：工作区 `/workspace`、Linux home `/root`、Ubuntu rootfs `/`、受管软件 `/opt/agentm`、宿主缓存。展示相对路径及宿主/guest 对应关系。
- 只读取目录元数据，不读文件内容，不提供编辑、删除或任意 Android 路径入口。
- 路径拒绝绝对路径、`..`、空段和符号链接；不递归追踪链接。Android 数据目录的系统别名先规范化，再限制具体应用根目录。
- 独立后台线程扫描。每类最多 1 秒或 50,000 项；扫描受限/读取失败显示「至少」和不完整提示。目录浏览每页 100 项，目录变化时可刷新。
- 显示普通文件逻辑字节数，硬链接按目录项计数，不等同于磁盘实际分配空间。
