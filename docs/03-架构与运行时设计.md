# 架构与运行时设计

本文件是待实现方案。源码依据见[调研](01-源码调研与选型.md)，用户流程见[产品规范](02-产品与React预览规范.md)。

## 1. 技术决策

| 决策 | 首版选择 | 原因与边界 |
| --- | --- | --- |
| Android 基底 | DSHA 运行时机制与必要依赖，渐进封装 | 有真实 PTY、进程身份与恢复路径；不是现成 SDK |
| 新业务 | Kotlin | 可调用 Java，不需要整体语言迁移 |
| 工作台 | React/TypeScript，Android 本地 WebView 加载 | 复用前端预览；React DOM 不等于 React Native |
| 终端 | 原生 Termux terminal-view/emulator 路线 | 保留 PTY、IME、复制粘贴、窗口 resize；模拟器不执行进程 |
| Agent Web UI | 单独原生 WebView | 不继承工作台高权限桥 |
| Linux | 单个 Ubuntu 24.04 arm64 用户态 | 与 DSHA 路径接近；版本由自有镜像锁确认 |
| 引擎 | proot 默认，首版不开放 UML | 先建立可靠基线；proroot 另做来源、许可和兼容验证 |
| Android 范围 | 首版 minSdk 30，targetSdk 以 DSHA 当前 37 为验证起点 | 不退回 28；发行政策与设备支持必须另行验收 |
| 分发 | 先提供自签名 APK 与自有更新清单 | 当前未指定应用商店；targetSdk 达标不等于商店准入 |
| 配置 | 文件管理，不做代理转换 | 保持用户原始范围 |

proot 提供 Linux 文件系统和用户态兼容，共享 Android 内核，不承诺 Docker、systemd、完整 namespace/cgroup 或内核模块。guest 的 root 不等于 Android root，也不是隔离不可信代码的安全边界。

## 2. 分层与所有权

| 层 | 职责 | 不拥有的职责 |
| --- | --- | --- |
| React Workbench | 页面、表单、状态展示、操作请求 | 进程、shell 命令、真实配置文件、长期密钥 |
| Kotlin Gateway | 消息校验、任务 ID、事件、页面与权限调度 | 直接模拟安装成功 |
| Kotlin Domain | Agent 注册表、配置事务、安装任务、session 管理 | 重新实现 proot 和终端模拟器 |
| Java Runtime Adapter | 对 DSHA 门面的调用、进程与安装依赖封装 | 产品五张卡片和提供商表单 |
| Native Runtime/PTY | 原生引擎、JNI、进程出生身份、TTY | React 生命周期 |
| Linux guest | Agent、工具链、项目任务 | 直接调用工作台管理桥 |

Android Application/Service 持有执行所有权；Activity 和 WebView 只是订阅者。所有耗时文件操作、解压、进程等待在后台执行，不阻塞 UI 或 JS 桥线程。

## 3. DSHA 的最小干预路线

第一阶段另建可运行技术分支：按 sources.lock.json 从远端取回完整 DSHA。examples 是精简参考源码，已经移除二进制、UI 和部分构建资产，不能直接在其中执行完整构建。

1. 使用独立产品工作目录/分支保留 DSHA 必要构建、生成资产与 JNI；更换 agentM 包名和签名，但初期可保留 Java namespace，减少资源与 import 变动。
2. Application 实现 RuntimeHostPorts.Owner，注入配置和诊断。既有 RuntimeTrial 所需 BrowserProbe 等依赖不能返回虚假成功。
3. Kotlin RuntimeFacade 只包装健康检查、安装操作、受限的结构化执行、PTY 打开与关闭。
4. 先保留 DSH 路径，通过原生测试页验证 Ubuntu 和 PTY；再接 React 本地页面。
5. 新增 AgentSessionManager，逐个接入其他 Agent；DshAdapter 暂时包裹原有 DSH 编排。
6. 有实际回归后，把运行时依赖移到 library module；删除无关 UI/设备能力时按依赖关系拆分，不能一开始整包裁剪。

需要真正改动的接缝：

| 接缝 | 现状 | agentM 工作 |
| --- | --- | --- |
| 包/资源/资产 | DSHA 单 app，生成 UiText 与锁定资产 | 审计依赖闭包；替换发行身份 |
| 启动参数 | ProotBootstrap 有执行/PTY 门面；PtySession.start 默认 shell | 新增一次性 argv+env+cwd 启动规格，保持出生身份捕获 |
| 环境变量 | RuntimeLauncher 注入 DSH PATH、bridge 兼容 NODE_OPTIONS | 按 Agent 分离；通用 Agent 不继承 DSH bridge 注入 |
| Web 管理 | HarnessController/WebProcessManager 以 DSH 为中心 | 引入 sessionId/generation，逐步抽出通用停止和健康判断 |
| 数据绑定 | UserDataLayout 面向 .dsh | 扩展托管路径表；系统与五个 Agent 持久数据分离 |
| 试运行 | RuntimeTrial 包含 DSH 认证/页面契约 | 抽出通用 shell/PTY 检测，DSH 检测仍由自身 adapter 负责 |

不要用自动转换把 Java 全改成 Kotlin，也不要假定保留 proot.so 就保留了整个稳定性机制。可暂时保留较大的 Java 依赖集合，代价是 APK/代码体积，收益是减少首轮行为变更。

## 4. RuntimeFacade 与 AgentAdapter

下面是设计接口，不是 DSHA 当前已有签名：

```kotlin
interface RuntimeFacade {
    suspend fun inspect(): RuntimeReport
    suspend fun prepare(plan: EnvironmentPlan): OperationId
    suspend fun execute(spec: CommandSpec): CommandResult
    suspend fun openPty(spec: PtySpec): SessionHandle
    suspend fun stop(handle: SessionHandle): StopResult
}
```

CommandSpec 采用 argv 数组、明确 cwd、env allowlist、超时和输出限制。产品入口只传 agentId/recipeId，不接受网页任意 shell 字符串。调用 DSHA 现有 String command 接口时，只能由可信 recipe 生成并使用统一 POSIX 参数转义；后续可加 argv 原生通道。

AgentAdapter 包括：probeInstalled、resolveInstallPlan、buildLaunchSpec、probeHealth、readConfig、planConfigPatch、collectDataPaths。适配器版本与 Agent 版本范围绑定；未知 schema 返回不支持，不能猜字段写入。

## 5. 文件与数据布局

以下为 agentM 目标布局，不代表直接移动 DSHA 目录即可兼容：

```text
files/
  linux/ubuntu/                    # 初期保留 DSHA rootfs 路径约束
  linux/lib/、linux/tmp/           # 引擎依赖与临时文件
  agentm/state/                    # 数据库、操作日志、安装 receipts
  agentm/data/                     # 五个 Agent 的配置、历史、缓存映射
  agentm/workspaces/               # 私有项目目录
  agentm/packages/<agent>/<ver>/   # 托管包槽位
  agentm/staging/                  # 尚未提交的安装/恢复候选
  agentm/backups/                  # 校验完成的恢复点
  agentm/logs/                     # 脱敏诊断，不包含密钥
cache/
  downloads/                      # 可清理下载缓存，不是唯一恢复副本
```

DSHA 提取初期先保持原数据协议；新增布局通过明确迁移和双向读回验证落地，不能同时保留两套都可写的配置真相。

guest 统一 HOME=/root，PATH 来自受管 Linux 工具链与当前 Agent 包，cwd=/workspace/<project>。将 `.claude`、`.codex`、`.pi/agent`、OpenCode config/data、`.dsh` 映射到各自持久目录；特殊环境变量见适配文档。

项目、Agent 数据与包槽位的映射是生命周期隔离，不是安全隔离。多个 Agent 仍在同一 Android UID 下。私有目录防止普通其他 App 直接读取，但执行中的 Agent 可以接触授予它的文件。

外部存储通过 SAF 导入/导出或 DocumentsProvider；SAF content URI 不是可直接传给 bash 的 POSIX 路径。开发项目优先在私有真实文件系统，避免共享存储的执行位、软链接、文件监控与性能问题。

## 6. 安装、更新与恢复事务

原生引擎优先随 APK 放入 nativeLibraryDir；系统镜像/工具链按锁定清单安装，基础环境不强依赖某一个 Agent 才能视为 ready。DSHA 现有 DSH 受管环境需在拆分时新增基础环境就绪定义。

基础环境支持离线完整包；标准产品可在此之上扩展可信镜像下载，不假定 DSHA 已提供任意网络镜像管理 SDK。

安装顺序：

1. resolve：固定版本、架构、来源与摘要，计算空间。
2. acquire：下载或读取随包资产；同源续传检查 Range/ETag，换源不能拼接不同版本字节。
3. verify：验证摘要和来源清单；镜像提供的自报摘要不能独自建立信任。
4. stage：解压到 staging，拒绝越界路径；合法 rootfs 绝对软链接按 guest 语义保留，但解压写入不能跟随其逃逸到宿主。
5. validate：解析 ELF/loader、实际 bash、Node/npm、git、DNS、PTY；Agent 做 --version 和自身健康检查。
6. commit：取得维护锁，必要时停止使用旧版本的会话，原子切换受管路径/receipt。
7. verify-after-commit：读回版本、配置和数据路径；确认成功后保留健康前代。

长任务状态持久化：operationId、目标、阶段、进度、取消能力、错误码、旧/新 receipt、结果。进程被系统回收后，从事务日志确定继续、回滚或人工修复，不能只删除 .installing 文件后假定成功。

MVP 包管理串行，避免 npm/系统包数据库并发写。运行中的旧 Agent 升级：先提示保存会话并停止，再替换版本；不在原目录边运行边覆盖。Agent 卸载默认仅删除包，保留配置与历史；删除数据是独立明确操作。

## 7. 会话与后台运行

SessionRecord 至少含 sessionId、agentId、generation、runtimeId、projectId、packageVersion、configRevision、launchTime、PID/出生身份、actualPort、desiredState、observedState。PID 不是稳定 ID。

生命周期：created → starting → awaiting-auth/ready → stopping → exited；异常为 failed/lost。取消启动也必须确认进程退出。旧代次的就绪、退出、健康回调一律丢弃。

停止流程：记录用户停止意图 → 禁止自动重启 → 请求优雅退出 → 在归属/出生身份仍匹配时进行受控终止 → 确认 guest 子进程结束 → 释放会话与维护锁。未确认则返回 unconfirmed，不准继续重装。

proot --kill-on-exit 与 proroot launcher 的行为不能混同。PTY 主从端、子进程树、退出状态、SIGWINCH/窗口大小、UTF-8 分片、背压均由底层会话管理；视图关闭不销毁会话。

前台 Service 托管活动任务；无 session 时环境可仍 installed/ready。通知显示活动会话数与停止入口。参考 DSHA 的 specialUse 前台服务声明，但类型合法性、后台启动限制、厂商省电和系统版本行为需实测，不能保证永不被杀。不要把永久终端放进有时间限制的 dataSync 服务设计。

异常恢复只恢复用户选择的 Web 服务，并使用有限次数/冷却策略；终端不自动重放命令，退出后新建终端需用户动作。恢复 Web 服务也不自动重新提交失败的模型请求或项目写操作。

## 8. Web 服务与桥接

工作台本地资产建议 WebViewAssetLoader 可信 origin；用 WebMessageListener/等价消息机制，严格检查来源和主 frame。协议按版本握手，请求带 requestId，事件带 epoch/sequence，返回只包含业务对象。

只暴露结构化方法：安装、启动、停止、配置预览/应用、查看状态、权限入口。不能暴露 execShell、任意文件读写或通用 Android 反射接口。

Agent WebView 不安装管理桥；即使 localhost 也不是天然可信。DSH 使用自身 token，OpenCode 使用版本支持的认证；默认只绑定 127.0.0.1。网络 origin 精确包含 scheme/host/port，外链打开系统浏览器，限制文件 URL、混合内容和调试功能。

首选端口占用时：保留用户首选值，申请备用/动态端口并读取实际监听地址；不杀占用进程、不把端口开放当健康证明。短期认证 URL 不写普通日志或持久 store，WebView 取得运行句柄后由原生注入/打开。

健康分三层：进程存在 → 认证 HTTP/协议可达 → 正确 Agent 页面或探针响应。权限等待、登录等待、服务繁忙不与异常退出混为一类。

## 9. 配置、秘密与权限

密钥由 Android Keystore 支持的本机存储管理，React 只收到 secretRef/hasSecret。用户输入密钥仅经专用提交路径处理，不进入日志、Redux devtools、URL 或 localStorage。CLI 必须读明文文件时，写私有目录 0600，备份默认排除或加密；不能宣称 Agent 使用密钥时仍对它不可见。

配置写入采用 parse → validate → 脱敏 diff → revision 检查 → 临时文件/fsync → rename → 读回。多文件写入有事务日志；回滚时也检查目标是否被外部修改，不能用旧备份覆盖新数据。JSONC/TOML 使用保格式 parser，禁止用正则直接替换整个文件。

首版权限只按功能申请：INTERNET、适当的前台服务、通知、可选电池优化、用户操作时的 APK 安装/文件选择。不继承 DSHA 的无障碍、ADB、Shizuku、Root、悬浮窗等设备能力作为基础安装要求。

## 10. 更新与诊断

应用 APK、引擎/rootfs、工具链、Agent 包、用户配置分别有版本与更新策略。UI 更新不重装 Linux；单 Agent 升级不更新整个 rootfs。镜像与 APK 清单固定身份、摘要、签名/可信分发来源和最低宿主版本，所有变更先验证后切换。

日志字段：时间、operation/session、generation、阶段、耗时、退出码、错误码、脱敏摘要。日志有大小/数量限制；不无限累计 stdout，也不把带 token 的启动行原样导出。诊断包包括版本和健康结果，不默认收集项目源代码、对话或凭据。
