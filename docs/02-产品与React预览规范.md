# 产品与 React 预览规范

本文件为 agentM 设计建议，未代表已实现。保留原始「首页、配置、环境、设置」四个底部入口。原文实际列出 **5 个 Agent、2 种使用形态**：Claude Code/Codex/Pi 为终端，OpenCode/DSH 为 Web UI。

## 1. 首版范围

用户可完成：环境安装 → 选择 Agent → 安装 → 选择工作目录与配置 → 启动 → 切页后回到同一会话 → 停止、升级、修复。

首版只提供一个 arm64 Ubuntu 环境，默认 proot。引擎是高级诊断信息，初次使用不要求用户比较容器技术。五个入口始终显示，真实安装能力按验证状态开放。

初版不包含多 Linux 发行版、多用户隔离、代码编辑器、Agent 消息聚合、请求代理、设备自动化、插件市场、远程 LAN 访问。保留后续扩展边界，不把这些加入当前页面的必选步骤。

## 2. 初次使用与修复入口

| 步骤 | 显示内容 | 操作与分支 |
| --- | --- | --- |
| 欢迎 | 本地开发环境、Agent 通过用户配置访问模型服务 | 开始；不声称所有数据永不离开设备 |
| 设备检查 | CPU、Android、可用存储、WebView、网络/离线包 | 不支持则解释；空间不足可重试；仅下载时要求网络 |
| 安装方案 | 推荐 Ubuntu；基础环境大小；可选 Agent 多选 | DSH 可作为推荐项；允许先装环境，稍后安装 Agent |
| 权限说明 | 通知；按需电池优化；工作区默认私有存储 | 拒绝非必要权限不伪装成功，也不阻断基础安装 |
| 安装 | 原生运行组件检查、系统解压/下载、工具链、自检、Agent 分项安装 | 查看日志、取消、失败步骤重试 |
| 完成 | 环境结果；每个 Agent 的安装结果 | 进入工作台；配置可稍后进行 |

基础环境安装失败：可进入受限工作台查看环境和日志，禁用启动。环境已就绪而部分 Agent 失败：允许进入首页，仅失败项显示重试。不能因为一个 Agent 失败重新解压整个系统。

任务进度由真实已下载字节、已完成阶段产生；未知总量使用不定进度。安装计划提前核算下载缓存、解压、新旧版本共存、回滚空间，不能只用压缩包大小。React 演示中的数字明确标记为模拟数据。

## 3. 首页

从上到下：环境状态摘要 → 当前工作区 → 正在运行的会话摘要 → 五张 Agent 卡片，固定顺序 Claude Code、Codex、OpenCode、Pi、DSH。

卡片显示：名称、终端/Web UI 标签、已装版本、安装状态、运行状态、配置摘要、主按钮；更多菜单放升级、停止、卸载、日志。版本与安装状态不能被一个 running 布尔值替代。

| 状态 | 主按钮 | 辅助操作/说明 |
| --- | --- | --- |
| 未安装且环境 ready | 安装 | 显示候选版本与预计用量 |
| 未安装且环境不可用 | 先准备环境 | 进入环境页 |
| 正在安装/升级 | 当前进度 | 查看日志；可安全取消时才显示取消 |
| 已安装、未运行 | 启动 | 配置、升级；缺凭据可进入原生登录/配置流程 |
| 启动中/等待认证 | 查看启动进度 | 取消启动；等待慢不能宣称崩溃 |
| 运行中 | 打开终端 / 打开 Web UI | 停止；再次点击连接已有 session |
| 正在停止 | 正在停止 | 禁止再次启动，直到退出确认 |
| 包损坏 | 修复 | 不显示成未安装；保留原配置 |
| 会话异常退出 | 重新启动 | 上次退出码、日志；不能当作包损坏 |
| 设备/版本不支持 | 查看原因 | 展示兼容性说明，不开放虚假安装 |

MVP 每个 Agent 一个活动 session；同一个按钮连点只产生一个启动任务。跨 Agent 并行数量由设备能力和设置决定，达到容量返回明确提示，不默默杀掉已有会话。

工作区选择只负责目录与项目名，不在首版内建编辑器。默认私有工作区，后续可通过导入/导出与 DocumentsProvider 访问。多个 Agent 指向同一项目时展示实际 cwd；不能假定配置目录不同就能防止项目文件互相覆盖。

## 4. 终端与 Web UI

### 终端页

顶部返回、Agent 名、项目名、状态、更多菜单；主体终端；底部辅助键 Ctrl、Esc、Tab、方向键及键盘开关。支持选择复制、粘贴、字体大小、横屏和软键盘变化。

返回首页只分离视图，session 仍由 Android Service 持有。关闭会话是独立操作。按下 Ctrl-C 发送终端中断，不直接杀整个 Linux 环境。旋转、切换主题与页面不可启动新 shell。

React 预览可用 xterm.js 或模拟终端视图展示屏幕状态，数据来自 MockGateway；生产首选 DSHA/Termux 原生终端 View。预览模拟不会执行用户输入命令，需有清晰「预览」标记。不能把 stdout 文本框当作生产 PTY。

### Web UI 页

显示原 Agent 页面，外层仅提供返回、刷新、连接状态、在系统浏览器打开、停止。页面加载失败区分服务未就绪、认证失效、WebView 渲染失败。重试连接不等于重启服务。

Android 中使用独立 WebView；工作台的高权限原生桥不注入 Agent 页面。OAuth/外部网页交给系统浏览器，当前运行仍保留。OpenCode/DSH UI 都不能在纯前端预览中假装已联网运行：预览用独立占位页说明连接状态，实际页面接入留给 Android 阶段。

## 5. 配置页

仅列出已安装 Agent（更新中或安装记录存在但损坏也可查看配置）。每项包含已保存的提供商、原生有效状态、配置文件来源、最近应用结果。

提供商编辑至少包含名称、协议、Base URL、模型、凭据状态和 Agent 特有字段。模型 ID 允许手工填写；不把所有提供商都假定支持 `/models`。存储的模板和 Agent 磁盘配置之间存在 revision，外部修改时显示冲突。

| 操作 | 行为 |
| --- | --- |
| 保存草稿 | 只保存 agentM 模板，不改变运行中的 Agent |
| 应用到 Agent | 先验证，展示脱敏差异，提交托管字段，记录配置 revision |
| 运行中应用 | 显示影响范围；默认留待会话停止后写入，可选择停止并应用 |
| 磁盘冲突 | 提供重新载入、保留草稿和查看差异；不盲目覆盖 |
| 删除提供商 | 不删除原生登录账号；当前使用项先解除选择或替换 |
| 查看密钥 | 默认只显示已设置；预览始终使用虚构值，不保存真实密钥 |

「已保存」「已应用」「下次启动生效」「当前会话实际使用」是不同状态。Pi 的 provider 条目启用不等于选择当前模型；DSH 的表单只覆盖已验证 schema，其余配置在原生 Web UI 内处理。细节见[适配规范](04-Agent适配与配置管理.md)。

## 6. 环境页

| 区域 | 内容/操作 |
| --- | --- |
| 运行组件 | 引擎版本、实际选用方式、兼容回退原因、自检 |
| Linux 系统 | 发行版、基础镜像版本、就绪状态、检查/修复/重装 |
| 工具链 | node、npm/pnpm、git、python、bash、PTY 检测结果 |
| 存储 | 系统、Agent 包、用户数据、项目、缓存、备份分别统计 |
| 日志 | 安装、会话、系统诊断筛选；按任务查看；脱敏导出 |
| 恢复 | 最近失败、可回滚版本、备份/恢复状态 |

proot 是每次启动进程的包装器，不是必然常驻的 Linux 虚拟机。没有活动 session 时可显示「环境就绪，暂无运行任务」，不要用虚构的 Linux 守护进程开关。

重装进入独立确认页，显示将停止哪些会话、替换什么、保留什么、备份状态、空间要求。默认保留项目、配置和历史；全部清空另设明确操作。停止尚未确认时不允许继续删除或替换 rootfs。

## 7. 设置页

- 外观：跟随系统、浅色、深色；字体与终端字号可分开。
- 打开应用自动准备环境：做健康检查；不等于每次启动全部 Agent。
- 自动恢复 Web 服务：单独开关；终端异常恢复不得重放上次输入。
- 重启运行服务：先展示受影响会话，不与重启手机混淆。
- 权限：真实授权状态和系统设置入口；没有权限时解释具体影响。
- 关于：agentM 版本、许可证、GitHub、检查更新；真实仓库 URL 尚未确定，预览不能伪造更新服务。

## 8. 状态与导航规则

状态采用三个维度：环境状态、包状态、session 状态。页面从共享 store 读取，不能各自猜测 installed/running。定义见 [workbench.ts](contracts/workbench.ts)。

- 查询快照后订阅事件；按序列号更新；发现缺口重新获取快照。
- 同一会话使用 generation 区分本次启动和旧回调；旧退出事件不能覆盖新启动。
- 原生任务返回 operationId 后显示进行中；Promise 接收成功不等于安装成功。
- 返回、隐藏页面、React 重挂载不取消原生任务。取消是显式命令。
- 本地预览允许刷新复位；生产状态以原生数据库和进程核对为准。

## 9. 必须能演示的模拟场景

| ID | 场景 | 验收点 |
| --- | --- | --- |
| fresh | 首次进入，无环境 | 线性引导可走完，可跳过 Agent |
| partial-install | 系统成功，两个 Agent 失败 | 首页能进入，失败项独立重试 |
| ready | 五项混合安装状态 | 安装/启动/打开按钮按状态变化 |
| terminal-active | Codex 终端运行 | 返回再进入还是同一 session |
| web-auth | DSH 等待认证 | 提示等待，重试页面不重启进程 |
| config-conflict | 编辑期间磁盘变化 | 冲突不丢草稿、不覆盖 |
| low-storage | 升级空间不足 | 展示所需空间，允许取消 |
| port-busy | OpenCode 首选端口占用 | 显示实际替代端口，不杀占用者 |
| process-lost | 系统回收服务 | 显示需恢复，终端输入不重放 |
| maintenance | 重装时有活动会话 | 确认、停止、备份、替换顺序可见 |
| rollback | 新包自检失败 | 恢复旧包，用户数据保持 |
| permission-denied | 拒绝通知/外部存储 | 按真实影响降级，非无限弹窗 |

## 10. React 组织建议

React + TypeScript + Vite，使用项目已有样式体系；当前目录没有现成前端工程，不在这次调研中替用户重建 UI。建议按 features/onboarding、agents、providers、environment、settings、sessions 拆分。

所有原生行为经 WorkbenchGateway；浏览器实现 MockGateway，Android 实现 NativeGateway。禁止页面直接访问 window.Android 任意方法、拼接 shell、读取真实密钥或通过 localStorage 声称完成安装。

按 360×800、412×915、横屏、大字号验证；触控目标至少 48dp 对应布局尺度，适配系统栏、键盘与 Android 返回。状态除了颜色也有文字，错误信息给出下一步动作。
