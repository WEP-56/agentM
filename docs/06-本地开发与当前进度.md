## 当前可运行内容

- `uiux-design/` 是正式复用的前端源码：Vite 7、React 19、Tailwind v4、Zustand、现有 Material 3 原型组件。
- `android/` 是新的 Kotlin Android 宿主，包名 `dev.agentm.app`，不会覆盖 DSHA 或原有 Flutter 应用。
- 工作台通过受 origin/main-frame 限制的 WebMessage 接口读取实际 Android 版本、ABI、WebView、可用存储、工作区、权限和日志。
- 原生设备终端采用 Termux terminal-emulator/terminal-view 与从源码构建的 JNI；支持 arm64-v8a 和 x86_64、终端输入、辅助键、页面返回与会话保持、显式关闭。
- 前台 Service 持有终端，Activity/WebView 不拥有 Shell 生命周期。应用被杀后不自动重放终端命令。
- 浏览器预览保留模拟交互；Android 模式覆盖模拟平台操作，不会把模拟安装、随机 PID、假版本和假存储用量当真实结果。

**当前终端是 Android `/system/bin/sh`，不是 Ubuntu。** Linux/rootfs、五个 Agent 的真实安装升级、Agent Web UI 和原生配置文件管理尚未接入。当前版本把这些显示为未就绪，不宣称完整 MVP 已完成。

## 为什么先做这一步

用户模拟器实际主 ABI 为 x86_64，系统 ABI 列表也包含 arm64 翻译能力；DSHA 参考基底主要面向 arm64。本轮先独立验证前端宿主与可跨两种 ABI 构建的真实 PTY，没有为了通过模拟器而伪造 Linux 就绪或降级 targetSdk。

这一步没有提取整个 DSHA SDK。下一阶段继续以 DSHA 的 proot/安装/进程与数据机制为依据接入 Linux，并明确 guest 子进程所有权；当前使用上游 Termux JNI，不具备 DSHA 扩展 JNI 的全部身份握手与备份能力。

## 常用命令

在工作区根目录执行：

```powershell
# 构建并覆盖安装到指定模拟器
.\tools\android.ps1 -Install -Serial emulator-5554

# 同时运行 JVM 检查、Lint 与真实 PTY 回归
.\tools\android.ps1 -Install -Test -DeviceTest -Serial emulator-5554

# 首次 npm 下载连不通官方源时
.\tools\android.ps1 -Install -UseNpmMirror
```

脚本使用 ANDROID_HOME/ANDROID_SDK_ROOT，未设置时查找用户默认 Android SDK，并生成忽略提交的 `android/local.properties`。APK 在 `android/app/build/outputs/apk/debug/app-debug.apk`。

前端独立预览：

```powershell
cd uiux-design
npm run dev -- --host 127.0.0.1 --port 5178
npm run typecheck
```

Gradle 会自动构建前端并同步 Vite 产物到 APK assets，无须手工复制 dist。只在 debug APK 开放 WebView 调试；生产版不开放。

## 本轮验证

- 前端 strict TypeScript 检查与 Vite 生产构建通过。
- Android Debug APK 构建、安装成功；arm64 与 x86_64 JNI 均构建成功。
- `BridgePolicyTest` 2 项 JVM 测试通过：可信主 frame、命令白名单、请求尺寸约束。
- Android Lint 通过（仍有依赖更新建议、弃用 API 与 WebView 静态分析提示；没有设置忽略所有错误的 baseline）。
- `TerminalLifecycleTest` 在 emulator-5554 通过：打开真实 PTY、执行命令、Activity recreate、离开再进入保留同一 PID/环境变量、停止退出。
- 用户发现的「试用终端」闪退已定位并修复：Termux 必须先调用 setTextSize 创建 renderer，再调用 setTypeface。修正版已覆盖安装，手工点击入口验证通过。

浏览器主页面经过 Playwright 检查。模拟器终端已截图检查。WebView 110 低于 Tailwind v4 推荐的 Chrome 111，下阶段需继续核对透明色等现代 CSS 的降级；不能把当前页面能打开等同完整视觉兼容认证。

## 紧接着做什么

1. 根据 DSHA 固定源码和可追溯资产实现 proot + Ubuntu 安装与基础工具探测，先验证 arm64，再决定 x86_64 guest 支持范围。
2. 把设备终端同一入口扩展为 guest PTY，保留设备终端作诊断；增加 guest 子进程停止与故障用例。
3. 先接一个 CLI 的安装/版本/启停/卸载，再逐个加入其余 Agent。
4. 复用 CC Switch 的相关 React 表单和配置语义；原生文件定位与读写走 Android bridge，不在页面里拼 shell。
