# 源码调研与选型

日期：2026-10-08。仅保留 DSHA 与 CC Switch 两个参考项目，提交见[锁定清单](../examples/sources.lock.json)。examples 已按移植范围裁剪，保留文件的原始内容与 SHA-256 可核对，不能直接当完整上游工程构建。

## 1. 结论与证据边界

**以 DSHA 为运行时参考，proot 为首版默认引擎，Ubuntu 为唯一首发系统；React 负责工作台，新增 Android 业务使用 Kotlin。** CC Switch 提供配置文件与包管理设计参考。

用户反馈 DSHA 实际使用非常稳定；源码也有进程身份、PTY、维护屏障、试运行和恢复机制，值得优先复用。当前克隆提交未必等于用户安装的 APK，本轮未构建或实测，不能把静态调研扩大成稳定性压测结论。

| 证据级别 | 含义 |
| --- | --- |
| 源码确认 | 阅读实际实现、构建配置或依赖锁 |
| 上游说明 | 官方资料、README、上游测试记录，不代表本轮执行过 |
| 用户反馈 | 本次会话提供的使用体验 |
| 设计建议 | agentM 待实现方案 |
| 待验证 | 需要固定版本、构建和真机验证 |

## 2. 两个项目的分工

| 维度 | DSHA | CC Switch |
| --- | --- | --- |
| 技术 | Java 17、Android View/WebView、JNI、脚本 | React 18、TypeScript、Tauri 2、Rust |
| 平台 | standard minSdk 30；low minSdk 23；targetSdk 37；arm64 | 桌面应用，不提供 Android Linux 环境 |
| 系统与运行 | Ubuntu 24.04 用户态；proot/proroot；DSH 在 guest 内 | 桌面 CLI 探测、安装和配置 |
| 终端 | Termux 终端组件与本地 JNI | 非 Android PTY 基底 |
| 配置 | DSH 专用，宿主密钥与数据事务 | 多 Agent、JSON/JSONC/TOML、冲突检测 |
| 更新 | 离线资产、分步修复、试运行、受管更新 | 来源锚定、CLI 安装升级 |
| agentM 新增工作 | 多 Agent、Kotlin 门面、React 桥、数据布局扩展 | 将相关语义转为移动端适配器 |

构建声明不等于 Android 全版本和 16 KB 页设备验收完成。精简范围、体积和重取方法见[参考源码说明](../examples/README.md)。

## 3. DSHA 的实际实现

| 模块 | 已确认行为 | 建议 |
| --- | --- | --- |
| ContainerRuntime | baseArgv/applyEnv/prepare 统一入口，proot/proroot 实现 | Java 保留，Kotlin 门面调用 |
| RuntimeHostPorts | Application 实现 Owner，注入设置、诊断、试运行页面检查 | 使用现有注入边界 |
| ProotBootstrap | 已变成安装、执行、终端协作者的兼容门面 | 保持依赖闭包，不只复制单文件 |
| TerminalRuntime/PtySession | 统一 argv/env，真实 PTY，native fork/exec 出生身份 | 保留握手，扩展 Agent 启动入口 |
| WebProcessManager | 按身份停止；区分 STOPPED/UNCONFIRMED/CANCELLED | 泛化为多会话，不能按端口清场 |
| MaintenanceCoordinator | 停止终端和 Web，再取得维护屏障 | 重装、升级、恢复共用约束 |
| RuntimeTrial | 静态检查后真实启动，记录运行方式，条件回退 | 新 Agent 增加独立验收器 |
| UserDataLayout/UserDataBindings | guest 路径与 rootfs 外持久数据域映射 | 扩展五个 Agent 数据布局 |
| HarnessService | 15 秒检查、代次核对、健康分类、重启冷却 | 泛化多个 session，不复制五个单例 |

ConfigStore.prorootEnabled 的缺省值是 proot；冷安装另有快速候选试用。WebRuntimeFallback.shouldRetry 要求 proroot 已退出、未鉴权、无插件故障、运行仍有效且未重试。启动慢不触发引擎切换。

### 文档与代码差异

- README/AGENTS.md 仍有 0.1.7-rc2 / 147；实际 Gradle versionCode 162，versionName `0.2.13-20261007.1000-dsh0.2.0-rc.2`，DSH 依赖锁为 0.2.0-rc.2。
- 旧说明概括数据在 Documents/dshdata；当前 UserDataLayout 有私有持久域 `user-data-v5/dsh`、legacy 与迁移判定，不能只按 README 迁移。
- 旧文档说必须 --link2symlink；当前 ContainerRuntime.Proot 只在硬链接探测不支持时启用。不能删除探测或无条件开启模拟。
- 历史签名和真机记录仅属于对应 DSHA 版本。agentM 用独立包名、签名和更新身份。

### Java 维护边界

采用保留、封装、渐进拆分，不全量翻译 Java。先在技术分支保留 DSHA 构建和必要资产，加入 Kotlin RuntimeFacade，验证安装、执行、PTY，再逐步拆成 library module。

DSHA 不是现成 SDK：ProotBootstrap 依赖 RuntimeHostPorts.Owner、backup/util、生成资源和资产；部分类型包可见；PtySession 依赖工作锁；HarnessController 是单 DSH 编排器。Java/Kotlin 可以同工程互操作，但这些依赖仍需处理。新增 Agent 管理和桥接不应继续塞入原 HarnessController。

### 许可与来源

DSHA 应用代码 MIT；第三方声明明确 proot GPL-2.0、Termux 终端子组件 Apache-2.0 例外、proroot v1.2.8 专有许可。部分标准版原生二进制精确来源修订未确认。首版以可追溯、可构建 proot 资产为目标；不能把根目录 MIT 扩展到全部 APK 资产。

## 4. CC Switch 的可借鉴部分

当前代码已有 Claude、Codex、OpenCode、Pi 配置，未发现 DSH 专用适配器。commands/misc.rs 提供 npm 映射、可执行文件枚举、来源识别、锚定升级。

- Claude 直接写入只修改托管字段，保留其他内容。
- Codex auth.json + config.toml 第二步失败时回滚第一步；仍不是跨文件原子事务，agentM 需崩溃日志与恢复。
- OpenCode 使用 JSONC 文档模型与磁盘冲突检测，同时识别 v1 `provider` 和 v2 `providers`，不能混写。
- Pi 管理 models.json 的 provider 条目；enable() 不等于当前会话 provider/model 切换。
- 升级现有位置和渠道，避免在另一个 npm prefix 装第二份。

本产品首版不移植请求代理、协议转换、故障转移、用量路由、托盘与 OAuth 托管中心。配置管理只支持 Agent 本身能直接使用的协议。
