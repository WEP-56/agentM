# 0.14.0 首页工作目录选择

日期：2026-10-09。用户要求在首页已有紫色 Ubuntu 组件内增加目录选择器，之后启动的终端类 Agent 在所选目录启动，WebUI 继续在自身界面选择项目。版本：`0.14.0-dev / versionCode 17`。

## 页面与使用

- 在紫色 Ubuntu 组件的状态说明和终端按钮之间加入「工作目录」入口，显示当前 Linux 路径，**不增加新的首页卡片**。
- 点击后打开目录弹层，可从现有 `/workspace` 工作区、`/root` Linux home 两个挂载根逐层浏览、返回上级、刷新或新建子目录。
- 只列出目录，稳定排序，每页 50 项；不进入符号链接。当前仅选择已绑定的应用私有 Linux 目录，不新增手机共享存储权限或外部挂载。
- 浏览、返回、新建目录都不改变启动偏好；点击「使用此目录」才保存。Android 返回键和 Escape 关闭弹层，取消保留原选择。
- 偏好由 Android `working-directory` SharedPreferences 持久保存，重启应用后仍有效；不依赖浏览器 localStorage。默认 `/workspace`。
- 所选子目录删除或不可访问时，在首页提示重新选择并阻止新终端启动，不悄悄改到别的项目目录。

## 启动与会话规则

| 入口 | 工作目录 |
| --- | --- |
| Claude Code、Codex、Pi 新终端 | 当前所选目录 |
| OpenCode TUI | 当前所选目录 |
| Linux 终端 | 当前所选目录 |
| 点击打开已有终端 | 保留原 PTY、进程和当前目录 |
| 终端菜单的显式重启 | 确认后在所选目录新建会话；确认框显示目标路径 |
| OpenCode / DSH WebUI | 保持原有启动方式，在 WebUI 内选择项目 |
| 设备终端 | 保持原有 Android Shell 工作区 |
| 环境检查、安装与软件探针 | 保持 `/workspace` 默认值 |

`TerminalManager` 只在真正创建新 PTY 时读取偏好，重进同一会话提前返回原 Session。重启先检查目标目录，目标无效时不先结束当前会话。Service 收到失败请求时保留正在运行的会话，并显示错误提示。

`LinuxRuntime.launch` 接收显式 `workingDirectory`，将对应 Linux 路径作为 proot 的独立 `-w` 参数，宿主 cwd 设置为同一个项目的实际私有目录。没有拼接 `cd` 命令，也不写命令到正在运行的 Agent，所以空格、中文及 shell 特殊字符按目录名处理。

终端标题在 Agent 未上报目录时显示其实际启动目录。Linux Shell 的 OSC 7 对空格、`%`、`#`、`?` 编码，防止路径被误识别为 URI 查询或片段。

## 入口与边界

- `WorkingDirectories.kt`：目录校验、列表、选择、创建及快照；复用 `StoragePaths` 的范围和符号链接校验。
- `AgentMApplication.kt`：原生持久化；`EnvironmentInspector` 增加 `workingDirectory` 快照。
- `MainActivity` / `BridgePolicy`：`listWorkingDirectories`、`setWorkingDirectory`、`createWorkingDirectory`，仅受信任的工作台主框架能调用。
- `TerminalManager`、`LinuxRuntime`、`TerminalActivity`、`TerminalService`：启动参数、目录显示和会话保留。
- `WorkingDirectoryPicker.tsx` / `Home.tsx`：同一紫色组件内的入口与目录弹层。
- 四类提供商配置文件、原生登录和 WebUI 配置不在本版修改范围；项目目录中的 Agent 原生设置照各 Agent 原生优先级读取。
