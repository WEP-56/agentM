# Pi 程序管理与本地工具验证

版本：0.7.0-dev；日期：2026-10-09。本阶段接入第三个 CLI Agent：Pi 1.1.0。工作台支持安装、检查、原生终端启停和卸载；配置通过 Pi 原生入口处理，模型调用与 arm64 真机仍需单独验收。

## 安装来源与依赖边界

使用官方 `@earendil-works/pi-coding-agent@1.1.0` 发布包中的 `dist/bundle/cli.js`。包内 CLI 已打包大部分 JavaScript 依赖，但代码执行与图片处理仍需要以下外置包：

| 组件 | 固定版本 | 用途 |
| --- | --- | --- |
| Pi CLI bundle | 1.1.0 | CLI、TUI、内置工具及其分块代码 |
| quickjs-wasi | 3.6.2 | QuickJS WebAssembly 运行时 |
| @silvia-odwyer/photon-node | 0.3.4 | 图片处理 WebAssembly |

三个原始 npm tarball 均先按官方 SHA-512 integrity 核验，再记录 Android 下载所需的 SHA-256、大小和来源。没有在 Windows 安装 Linux node_modules，也没有运行 npm 生命周期脚本。两个外置包无传递 dependencies；完整保留包内容及许可证。Pi bundle 的各个 JS 分块以及依赖的 JS/WASM/扩展文件均列入启动前的路径完整性检查。

这是一份针对发布 CLI bundle 的受管 recipe，不是完整 npm SDK 依赖树。额外扩展、第三方插件、特殊提供商可选依赖不在本阶段认证范围内。

Pi 使用现有 Node.js 24.21.0；安装时补齐 Ubuntu 的 `ripgrep` 和 `fd-find`，避免首次打开时由 Pi 自动下载搜索工具。系统工具沿用 Ubuntu APT 的仓库与签名校验策略，实际版本记录在检查输出中，不将 APT 仓库版本描述为固定 npm 资产。

## 程序、数据与会话

Pi 使用独立 `pi-<UUID>` 安装槽位。下载、依赖解压与检查在未发布槽位中完成，全部通过后才原子更新安装记录。失败不替换现有安装；卸载只删除选中的受管程序槽位。`/root/.pi/agent`、工作区、Claude/Codex 槽位不随 Pi 卸载删除。

受管 `bin/pi` 入口通过 PATH 中的受管 Node 启动原始 bundle，并设置上游支持的 `PI_SKIP_VERSION_CHECK=1`。默认工作目录为 `/workspace`；不改写 Pi 的 models.json、settings.json、auth.json 或项目可信设置。可在原生终端中用 `/login` 登录、`/model` 选择模型。工作台提供商模板目前仍只支持 Claude。

当前仍只有一个活动 PTY。返回工作台或 Activity 重建保留进程；再次打开连接同一会话。切换其他终端或管理软件之前需关闭当前会话。

## 本地探针与验收

安装和“检查版本”都会在独立临时槽位中执行以下检查，设置独立 `PI_CODING_AGENT_DIR` 和离线模式，避免读取用户 Pi 凭据或项目扩展：

1. 实际执行 `pi --version`，要求输出与固定版本一致。
2. 通过发布 bundle 导出的内置工具执行中文文件写入、读取、编辑、Shell 命令、grep 和 find。
3. 加载 QuickJS WASM 并计算表达式；加载 Photon WASM 并创建/检查图片。
4. 检查退出码和完成标记，随后清理本次临时槽位。

这些探针证明本地工具和 WASM 能在当前运行时执行，不等于已经验证模型选择、认证或模型驱动的工具调用。Pi 与其他 Agent 共用 Android UID / proot 环境，也不提供额外的宿主安全隔离承诺。

本轮在 Android 15 / API 35、x86_64 模拟器通过设备回归：真实安装、检查结果、缺失 WASM 时拒绝启动、PTY、Activity 重建和返回重入、维护互斥、停止、卸载重装和数据保留。Claude/Codex 的受管槽位保持不变。首次探针因使用旧 edit 参数格式失败；已按 1.1.0 的 `edits` 数组契约修正后重新通过，失败时未发布 Pi 槽位。

TypeScript strict、Vite 生产构建、APK 构建及 13 项 JVM 测试通过；Lint 为 0 错误、23 警告。设备 Shell 和 Pi 集成回归各 1 项通过。Pi 检查实际输出：

```text
1.1.0
ripgrep 14.1.0
fdfind 9.0.0
AGENTM_PI_TOOLS_OK: read/write/edit/bash/grep/find
AGENTM_PI_WASM_OK: QuickJS evaluation / Photon image
```

另用 Playwright 连接 APK 的实际 WebView，确认 Pi 卡片版本与启动入口；原生终端显示 1.1.0，执行 `!printf AGENTM_PI_TUI_OK` 得到预期输出，返回按钮保留同一 Pi 进程。未配置模型时，Pi 显示原生登录提示。截图和详细日志保存在本机 `output/android/`，摘要见 [0.7.0 验证结果](validation/0.7.0.json)。未进行模型请求、OAuth 登录或 arm64 真机验证。

```powershell
node tools/prepare-pi-catalog.mjs
$env:JAVA_HOME = 'C:/Program Files/Java/jdk-17'
.\tools\android.ps1 -SdkPath E:/androidsdk -Install -Test -DeviceTest -PiTest -Serial emulator-5554
```

`-SdkPath` 用于指定现有 SDK；不传时仍读取 ANDROID_HOME、ANDROID_SDK_ROOT 或用户默认目录。本机原文档中的默认 SDK 路径已失效，本阶段使用 E:/androidsdk 并补齐既定 NDK/CMake 版本。

后续按用户最新确认的顺序推进：先接通 OpenCode 与 DSH，再由用户完整测试并共同打磨，完成后再开展 CC Switch 相关配置管理扩展。Pi 模型回复/工具调用及 arm64 真机列入用户验收矩阵。Codex 沙箱阻塞仍按 [0.6.0 记录](11-Codex程序管理与兼容性.md)保留。
